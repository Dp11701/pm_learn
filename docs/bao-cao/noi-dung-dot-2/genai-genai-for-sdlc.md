## genai-genai-for-sdlc

- Kiểm parser: GenAI / GenAI for SDLC (chu-de) · Đủ khối 9/9
- Nguồn đã mở: [Announcing the 2025 DORA Report: State of AI-assisted Software Development — Nathen Harvey, Derek DeBellis, Google Cloud Blog](https://cloud.google.com/blog/products/ai-machine-learning/announcing-the-2025-dora-report); [To vibe or not to vibe — Birgitta Böckeler, martinfowler.com](https://martinfowler.com/articles/exploring-gen-ai/to-vibe-or-not-vibe.html); [Coding Assistants Threaten the Software Supply Chain — Jim Gumbley, Lilly Ryan, martinfowler.com](https://martinfowler.com/articles/exploring-gen-ai/software-supply-chain-attack-surface.html); [Best practices for using GitHub Copilot — GitHub Docs](https://docs.github.com/en/copilot/get-started/best-practices); [OWASP Top 10 for LLM Applications 2025 — OWASP GenAI Security Project](https://genai.owasp.org/llm-top-10/) (kèm trang LLM01 Prompt Injection, LLM06 Excessive Agency, LLM09 Misinformation); [DORA metrics guide — DORA](https://dora.dev/guides/dora-metrics/), [What is MCP — Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro), [GitHub Copilot features — GitHub Docs](https://docs.github.com/en/copilot/get-started/features), [Exploring Generative AI (trang mục lục loạt bài) — martinfowler.com](https://martinfowler.com/articles/exploring-gen-ai.html) (mở để kiểm, không thêm vào bài vì đã đủ 5 nguồn)
- Agent soát đã sửa:
  - Vì sao PM cần biết: "DORA ghi nhận dùng AI vẫn có quan hệ tiêu cực với độ ổn định; nghĩa là code viết nhanh hơn chưa chắc release nhanh hơn hay ít lỗi hơn" → "có quan hệ tích cực với throughput nhưng vẫn có quan hệ tiêu cực với độ ổn định giao hàng; nghĩa là giao nhanh hơn chưa chắc đã ít lỗi hơn". Bài blog DORA nói rõ năm nay thấy quan hệ tích cực với throughput, nên câu cũ ("chưa chắc release nhanh hơn") dễ đọc thành trái với nguồn.
  - Coding agent: "(ví dụ qua MCP server, giao thức nối AI với công cụ khác)" gọi nhầm server là giao thức → "MCP là chuẩn mở để nối ứng dụng AI với công cụ và dữ liệu bên ngoài", theo định nghĩa trên modelcontextprotocol.io.
  - Prompt injection: "khiến AI làm khác ý người dùng" mâu thuẫn với trường hợp chính người dùng gõ thẳng chỉ dẫn → "khiến AI hành xử ngoài ý muốn", khớp OWASP LLM01 ("alter the LLM's behavior or output in unintended ways").
  - Probability, impact, detectability: "nhờ test, kiểu dữ liệu" → "nhờ test, ngôn ngữ có kiểm tra kiểu (typed language)", đúng ý Böckeler hỏi "Are you using a typed language?".
  - Ví dụ thực tế: giải nghĩa change fail rate "tỉ lệ thay đổi gây lỗi trên production" → "tỉ lệ lần deploy phải xử lý gấp như rollback hay hotfix", theo định nghĩa trên dora.dev (khớp cách bài ci-cd và quality-metrics dùng tên chỉ số).
- **Nên tự kiểm lại:**
  - Ý DORA chỉ lấy từ bài blog công bố báo cáo, chưa đối chiếu bản PDF đầy đủ. Đã khớp: "AI amplifies what's already there", quan hệ tích cực với throughput, tiêu cực với stability, lời khuyên làm rõ chính sách AI và củng cố lưới an toàn. Bài blog không nhắc change fail rate; việc bài dùng change fail rate, cycle time để đo là gợi ý của người viết.
  - Ví dụ nguồn chứa prompt injection: OWASP chỉ nêu "websites or files", Gumbley và Ryan nêu MCP server, rules file, phản hồi của công cụ/API. "README" và "issue" là suy ra từ hai nguồn đó, không nguồn nào ghi đúng hai chữ này. Bài của Gumbley và Ryan cũng không dùng chữ "prompt injection".
  - Câu "cùng một sản phẩm có thể có cả hai chế độ" là nhận định chung; trang GitHub Copilot features cho thấy một sản phẩm vừa có inline suggestions vừa có chế độ agent sửa file và tạo PR, nhưng bài không dẫn trang này.
  - Bài Gumbley và Ryan không ghi ngày trên trang; trang mục lục loạt bài ghi 13/5/2025. Nội dung về công cụ AI đổi rất nhanh, nên xem lại các nguồn trước khi áp dụng.
  - Phần lớn Cách áp dụng, Góc dev lead → PM, bảng So sánh (đặc biệt "review và test là chỗ AI dễ làm nghẽn nhất", danh sách rủi ro cho risk register, "không tự merge hay deploy") là tổng hợp và nhận định của người viết dựa trên các nguồn, không phải quy trình chuẩn của một tổ chức.
